# Handover: stages B0 and B1

12 November 2026. Synthetic data only.

## What works

- Project foundation: Django 5.2 on PostgreSQL 16, migrations, test runner, demo data, health check (`/healthz`), Docker Compose file and a CI workflow. Stack choice: `docs/decisions/0001-stack.md`.
- Masters, users, roles and permissions, with every change recorded.
- Inwards: enter (draft), edit with a reason, receive into stock once, lock.
- Weight-only stock goes straight into a weight balance and locks its inward on confirmation.
- Supplier invoices as book records, linked to receipts, with no stock effect.
- History of every action and every refused attempt. History and the stock ledger are append-only in the database.

## Still blocked, by decision

- **O01**: no correction of a locked inward, and no mixed tagged/weight-only inward.
- **O02**: tolerances are demo settings only and are not applied.
- **O11**: invoices cannot be edited after entry; no settlement or GST treatment.
- **O12**: demo roles and a local demo only.

## Limitations

- The Docker setup was written but not run in the build environment, which has no Docker daemon. The non-Docker path and all tests were run there.
- No devices are involved in this increment, so nothing is simulated yet. Printer, scale and RFID adapters start in stage B2.
- A wrongly confirmed weight-only receipt cannot be corrected in the app until O01 is decided. The confirmation screen warns about this.
- The first-lot lock exists as a function for stage B2 to call. It cannot be reached from any screen yet.
- Supplier invoices are not tax-compliant purchase entries.
- No password reset by email; a user with `access.manage` sets passwords.
